# cad-lab-studio
<img width="1816" height="624" alt="扫码_搜索联合传播样式-白色版" src="https://github.com/user-attachments/assets/b2c15459-1212-4b3c-ae7f-94c672b320ce" />

独立可部署的图纸建模工作台：解析 DXF / DWG → 提取墙带与楼板 → 逐层堆叠 → 叠加屋顶 / 底座 / 大门 / 墙面立面四类程序化构件。

产物有两条出口：**GLB**（自带材质与细部的完整模型）与**建筑包 GeoJSON**（可回灌 webmap 编辑器继续编辑的轻量矢量包）。

本子工程由 webmap 仓库 `src/cad-lab` 试验台抽取而来，采用**快照式复制**：复制件独立演进，webmap 现有实现不受任何影响。

> 子工程与 webmap 共用同一套程序化构件源码（`facade / roof / podium / gate`），
> 因此两端的构件参数、面序号语义与材质字段完全同构 —— 这是建筑包能在编辑器里
> 按原配置重建构件的前提。修改其中一侧的构件配置结构时，必须同步另一侧。

## 项目定位

本工程主要作为**基于 Cesium + Three.js 的 3D 编辑器系统的辅助功能**使用，本身不是编辑器。

核心功能只有两件事：

1. 解析 CAD 图纸（DXF / DWG 的墙带、楼板、门窗与图层语义）；
2. 把解析结果导出为 3D 编辑器可直接消费的两种格式 —— **GLTF**（`glb`，自带材质与细部的完整模型）与**自定义语义化结构 GeoJSON**（建筑包，保留逐层、构件参数与语义标签）。

目标是把「照着图纸手搓建筑模型」简化成「导图纸 → 导出 → 导入编辑器」三步：
编辑器负责后续的落位、布局、导航与业务数据，本工程只负责把图纸变成可编辑的初始模型。

## 独立使用

```bash
npm install
npm run typecheck   # 类型检查
npm test            # 单元测试
npm run build       # 类型检查 + 生产构建（输出 dist/）
npm run preview     # 本地预览产物
```

构建产物使用相对基址（`base: './'`），可部署在任意子路径；WASM 从 `wasm/libredwg-web.wasm` 相对加载。


## 墙体闭合

图纸里常见「外墙未闭合」：墙带是若干条开放链，无法形成闭合环，因此屋顶 / 底座 / 大门 / 立面会报告缺少轮廓。

平面视图工具栏的「闭合墙体」按钮提供**手动**闭合（不做自动闭合）：进入绘制态后，点击「绘制地板轮廓」旁的「闭合墙体」，在平面上画出连接线，双击 / Enter 提交。

- 连接线是真实墙段，不是楼板；提交后与既有墙链一起参与拓扑，生成闭合墙环。
- 不限制落点：画的每一段直线都会生成墙体，两端不必落在既有墙链端点上，也不要求一次就闭合。
- 折点若离既有墙段端点 0.3m 以内，会自动对齐到该端点（含中间折点），抵消墙带半厚造成的视觉偏差，让连接线真正与墙带焊接。
- 每段连接线独立匹配它所连接的墙体：优先继承该段起点所连墙段的图层与墙厚，起点悬空时继承终点所连墙段；两端都未连墙时取「墙线最长图层」已解墙段的中位厚度 —— 是图纸证据，不是硬编码的全局默认值。
- 连接线只支持直线段，避免圆弧采样出大量碎墙段破坏墙链。

闭合成功后，闭合墙环可作为建筑外轮廓（`resolveBuildingOutline` 的第二优先级），内 / 外墙面与依赖轮廓的构件随之可用。

## 导出建筑包 GeoJSON

生成楼层模型后，楼层页工具栏的「导出建筑包 GeoJSON」会下载 `<图纸名>-building.geojson`：

- 顶层带 `webmapBuilding` 块（`schemaVersion: 'webmap-building/1'`），记录 `buildingId`、`name`、平面中心 `origin` 与逐层 `levels[]`（`f0..fN`、标高、层高、板厚、材质）。
- 坐标为局部米制：原点取建筑平面中心，y 轴与图纸 y 轴同向；**不含经纬度**，由编辑器导入时一次性锚定。
- 墙体是 `MultiPolygon`，直接取墙带边界（外环 + 内环），不做轮廓挤出；楼板是独立 `Polygon`，未绘制地板轮廓时不输出。
- 几何相同的楼层用 `levels[].geometryRef` 指向首个楼层，不重复输出；逐层删墙后该层自动独立。
- 导出前统计层数与唯一几何顶点数，超过阈值先弹确认，不做静默裁剪。

### 构件与材质跨端还原

建筑包除了几何，还要把「构件怎么摆、用什么材质」一起带走，否则编辑器里只剩纯色白盒：

- `buildings[].outline`：程序化构件使用的整栋外轮廓（局部米制、逆时针、首尾点相同）。`entranceGates[].faceIndex`、`frontFaceIndex` 都以这条轮廓的边序为准。
- `buildings[].frontFaceIndex`：正立面边序号，没有大门时供底座 / 屋顶对齐使用。
- `levels[].appearance`：逐层构件外观，字段名与 webmap `render3d` 完全一致
  - `facadeStyle`：立面风格；
  - `podium`：底座配置，仅首层，且只在 cad-lab 实际生成过底座时写入；
  - `roof`：屋顶配置，仅顶层，同样只在实际生成过时写入；
  - `entranceGates`：大门配置，仅首层。
  - 未生成对应构件的楼层不写该字段（不是写 `{}`），避免导入侧误判为「已启用」。
- 墙体要素另带 `properties.outline`（WGS84），供编辑器拉伸「装饰宿主」承载构件。

编辑器导入时按 `appearance` 用**同源构建器**重建底座 / 屋顶 / 立面 / 大门，材质参数（颜色 / 金属度 / 粗糙度 / 贴图）随配置一起生效。

> 导入期的坐标系换算：cad-lab 轮廓在图纸平面 `(x, y)` 上逆时针，编辑器室外场景平面是
> `(x, -y)`，同一个环会变成顺时针。导入时统一反向，并把面序号映射为
> `编辑器面 j ↔ cad 面 (n - 2 - j + 2n) % n`（`n` 为环顶点数），保证 `faceIndex` 不错位。

> 版本不匹配（非 `webmap-building/1`）时导入侧**直接报中文错误**，不做降级解析。

在 webmap 编辑器 View3D 室外模式点击「导入建筑」，选择该文件即可：以当前视图中心为锚点落位，逐层渲染墙体、楼板与四类程序化构件，点击可选中单层。

## 导出 GLB

楼层页的「导出 GLB」会下载 `<图纸名>.glb`，内容包含完整的材质与细部：

- 墙体携带当前材质参数（颜色 / 金属度 / 粗糙度）与表面贴图（石膏的颜色 / 粗糙度 / 法线，铺了立面时为立面贴图），并按米制盒式投影生成 UV；贴图的 repeat 由 `KHR_texture_transform` 表达。
- 屋顶 / 底座 / 大门 / 立面四类程序化构件按所属楼层标高与墙体一起导出，材质与贴图（含大门牌匾的 Canvas 贴图）随节点写入，节点名形如 `procedural-roof-0`。
- 构件与墙体使用同一套换算（平面中心归零 + z 镜像）：构件挂在 `procedural-decor` 节点下，用负 z 缩放表达镜像，加载方按 glTF 规范翻转绕序即可正确渲染。
- 多层墙体和门窗仍按标高烘焙为合并网格，manifest 写入场景节点的 `extras`。

## 当前不足与限制

以下是已确认存在、尚未实现或有意不做兜底的边界。使用前请先对照，避免把「预期内缺失」当成 bug。

### 门窗尚未跨端还原（最大缺口）

cad-lab 内部的门 / 窗 / 门连窗 / 玻璃幕墙建模是完整的：`role: 'opening'` 要素会带上
`openingKind`、洞口尺寸、宿主墙绑定（`semantic`）与 `render3d` 里的门扇 / 窗档案。

但 **webmap 导入侧只识别 `walls` 与 `slab` 两种 role**，门窗要素会被整体跳过：

- 导入后是**实心墙**，没有门窗洞口，也没有门扇 / 窗扇 / 幕墙玻璃。
- 门窗语义只在 GLB 导出里保留。
- 补齐它需要编辑器侧增加窗与幕墙几何构建器、以及门的室外 WGS84 分支，工作量与本次构件对齐不在同一量级。

### 轮廓与装饰宿主

编辑器里墙体是墙带 `MultiPolygon`，没有逐面 `material group`，无法直接挂构件。
因此导入时会按 `properties.outline` 拉伸一根**不可见宿主棱柱**（材质 `visible = false`，不参与拾取），
侧面逐面切 group 承载构件。这带来三条硬限制：

- **轮廓顶点上限 96**。超过上限时宿主直接不生成（不做抽稀 —— 抽稀会让 `faceIndex` 与导入的
  `entranceGates[].faceIndex` 错位），表现为底座 / 屋顶 / 立面 / 大门全部不显示，只剩墙体和楼板。
  复杂异形、圆弧采样密集的平面容易命中。
- **只按整栋外轮廓逐面生成立面浮雕**。内院、内部墙环没有浮雕；cad-lab 侧只是给所有墙体换上
  同一份立面贴图（`setWallFacadeTexture`），两侧观感因此不完全一致。
- **沿面方向约定相反**。cad-lab 的轮廓边方向与编辑器（轮廓被反向）正好相反，面序号是一致换算了，
  但沿面方向没有：立面花纹（窗格排布）会沿面镜像，大门的 `offsetT` 也会镜像 ——
  门仍落在正确的面上，只是沿面位置左右颠倒。导入侧目前只换算 `faceIndex`，未换算 `offsetT`。

### 外轮廓解析

`resolveBuildingOutline` 的优先级是「手绘楼板轮廓 → 面积最大的单个闭合墙环」：

- **取最大的一个环，不合并多环**。多栋连体（多个闭合环）只认面积最大的那栋，其余环不参与构件生成。
- **不自动闭合墙链**。外墙未闭合时轮廓为空，四类构件全部缺失，只能导出墙体与楼板；
  必须手动点「闭合墙体」画连接线。
- 轮廓退化（面积为零、顶点不足、墙带左右边界缺失）同样直接判空，不会退回包围盒之类的近似。

### 墙厚

墙厚**没有全局默认值**，按以下顺序取图纸证据：双线平行配对实测 → 面板手填 / 图层名里的厚度标注
（如 `A-WALL-200`）→ 同图层已解墙段 → 平行墙线实测间距 → 端部相连墙段回填。
全部证据都取不到的**单线会被跳过**，并在面板提示图层名；这是刻意的空值而非兜底。

### 变换与重生成

- 整栋旋转 / 缩放会同步 `properties.outline`，但构件是按轮廓边序和尺寸生成的；非等比缩放或
  大幅变形后，立面浮雕、前场台阶、大门雨棚可能与墙带出现偏差，需要重新生成构件。
- 建筑包导入后按 `buildingId` 去重：同一栋楼已导入过楼层、或已绑定 GLB 模型时会直接报中文错误，
  必须先删除旧数据再导入。

### 其他

- **坐标不含经纬度**。建筑包只有局部米制坐标，具体落位由导入时的视图中心决定；换一个视图中心导入，
  位置就会不同。
- **DWG 兼容性依赖 `@mlightcad/libredwg-web@0.8.6`**。较新的 DWG 版本或非常规实体可能解析失败，
  失败信息沿用上游库的报错，没有做二次归纳。
- **子工程与 webmap 是快照式复制**。`src/lib/{facade,podium,roof,gate}` 是拷贝件，不是共享包；
  修改构件配置结构必须两端同步，否则建筑包在编辑器侧会解析出错。
- 测试覆盖偏几何（面序、法线、group 切分、墙厚证据回填），**没有端到端的「导出 → 导入 → 渲染」集成测试**，
  跨端效果仍以人工导入实测为准。
